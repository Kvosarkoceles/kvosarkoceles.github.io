ClinovaMex

Plataforma multi-tenant para la operación de farmacias y consultorios: inventario, ventas, pacientes, citas, recetas y pólizas en una sola API y un panel de administración. El proyecto cubre las tres aplicaciones, el modelo de permisos y los entornos de trabajo.

El reto

Una farmacia con consultorio no opera con una sola lista de tareas: convive con inventario, ventas, recetas, citas, pólizas, sucursales y distintos roles que no deben ver la misma información. La mayoría de las herramientas resuelven una parte del problema y obligan a separar el resto en hojas de cálculo o sistemas aislados.

El objetivo fue construir una plataforma que centralizara esa operación, con aislamiento de datos por farmacia y sucursal, permisos granulares y una experiencia usable para el personal del mostrador, el consultorio y la administración de la plataforma.

La solución

ClinovaMex se compone de tres aplicaciones sobre una misma API y una misma base de datos PostgreSQL:

App de farmacia

React, Vite y Tailwind CSS. Cubre inventario, ventas, pacientes, citas, consultas, servicios, recetas, pólizas y reportes.

API

Node.js y Express sobre PostgreSQL. Autenticación con JWT, reglas de negocio, documentación con Swagger y auditoría de acciones administrativas.

Panel de plataforma

React y TypeScript. Alta de clientes, administración de sucursales, matriz de roles y permisos, y seguimiento de la operación.

Decisiones técnicas

  • Multi-tenant con contexto en el servidor. El tenant, la farmacia y la sucursal salen del contexto autenticado, nunca del cliente. Un acceso cruzado entre tenants se responde como inexistente.
  • Permisos en la base de datos. Cinco roles y 42 permisos administrables desde el panel. Un cambio de permisos se aplica sin desplegar y queda registrado en la auditoría.
  • Migraciones versionadas. 60 migraciones con versión hacia arriba y hacia abajo, aplicadas por un runner que registra el estado en la base de datos.
  • Entornos separados. Local, test y producción comparten la misma definición de Docker Compose, con scripts de arranque y respaldo en Python y Bash.
  • Operación de mostrador. Impresión de tickets de 80 mm y recetas, escáner de códigos de barras, temas por cliente y almacenamiento de imágenes desacoplado.

Herramientas de IA

El desarrollo se apoya en agentes con modelos locales servidos por Ollama: Qwen2.5 14B para código y datos, Qwen2.5-VL 7B para visión y Ornith 9B para tareas generales. DeepSeek actúa como supervisor para planificación, revisión y desbloqueo, y Playwright MCP se usa para validar interfaces y flujos en el navegador. La automatización de tareas y el bot de Telegram se apoyan en Python y Bash.

Resultado

El producto quedó completo en sus tres aplicaciones: una API documentada, un frontend para el personal y un panel de plataforma, con un modelo de permisos de 42 acciones, 60 migraciones versionadas y tres entornos de trabajo. El proyecto sigue en evolución.

Qué aprendí

La parte difícil de un producto multi-tenant no es el CRUD: es decidir dónde vive el contexto, cómo se auditan los cambios y cómo se evita que un permiso nuevo rompa una pantalla que ya funcionaba. También confirmé que los agentes de IA rinden más cuando el trabajo se reparte por tipo de tarea y no cuando todos los modelos pasan por todo.

El código y el entorno de ClinovaMex son privados. Este caso de estudio documenta la arquitectura y las decisiones sin exponer datos de clientes ni credenciales de acceso.
